# **<span align="center">Schema Configuration</span>**

<br />

Once the **Extract**, **Transform**, and **Load** stages have been successfully configured, it is necessary to complete the setup by configuring the **Schema** stage. This step defines how the collected data will be structured and interpreted by the database and Viewtisight.

To begin, click on the **SCHEMA** button from the main Plugin Creator menu.

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/schema-button.png" align="center"></figure>

<br />

---

## **Initial State and Model Settings**

Upon entering the Schema configuration, the system automatically attempts to fill in the **Model Settings** based on the pipeline's name. It will pre-populate the destination table name (`Set`) and the default retention policies.

However, if you scroll down to the **Fields** section, you will notice that it is completely empty. The platform does not automatically know which columns exist in your data stream until you explicitly tell it to read them from the previous stages.

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/schema-empty-fields.png" align="center"></figure>

<br />

---

## **Populating Fields**

To automatically import the structure of your data, you must use the **POPULATE FROM PREVIOUS STAGE** button located at the top right of the screen.

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/schema-populate-button.png" align="center"></figure>

<br />

Clicking this button triggers the platform to read the final grid output generated by the **Transform** stage. It then automatically creates a corresponding database column for every field present in that grid.

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/schema-populated-fields.png" align="center"></figure>

<br />

---

## **Automatic Metric and Dimension Assignment**

When the fields are populated, the V.S. Data Broker applies intelligent defaults to categorize each field as either a **Metric** or a **Dimension** based on its data type:

-   **Dimensions:** String fields (text) are automatically categorized as Dimensions. These are used to filter, group, and categorize your data in dashboards (e.g., `host`, `interface`, `city`).
-   **Metrics:** Numerical fields (`int64`, `double`) are automatically categorized as Metrics. These are the quantifiable values that will be measured and aggregated (e.g., `interface-in-octets`, `interface-in-errors`).

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/schema-metric-dimension.png" align="center"></figure>

<br />

While the platform assigns these default roles automatically, you maintain full control to adjust them. You can manually change a numerical field from a Metric to a Dimension if it represents an ID rather than a measurable value.

<br />

---

## **Simple Calculated Metrics and Units**

For those fields categorized as **Metrics**, the Schema stage provides the ability to create **simple calculated metrics** directly during insertion (the full concept of calculated metrics is explained in detail in the Viewtisight guide). 

To configure a simple calculated metric from this stage, simply open the dropdown under the **Agg. Function** column for the desired metric and select the appropriate aggregation function (e.g., `sum`, `avg`, `max`, `count`).

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/schema-simple-metrics.png" align="center"></figure>

<br />

Additionally, you can define the base **Unit** of the metric in the `Units` column (e.g., `bps`, `bytes`, `ms`). 

> [!NOTE] **Scaled Units**
> If your unit of measurement requires scaling for display purposes (for example, converting `bps` into `Kbps`, `Mbps`, or `Gbps` automatically in dashboards), this scaling configuration must be done later from the **Metrics Composer** (how to work with this feature is explained in the Viewtisight guide). The Schema stage only defines the base unit.
