<h1><strong><span align="center">Prerequisites for WinRM Connector</span></strong></h1><p></p><p>Before configuring the <strong>Windows Remote Management (WinRM) Connector</strong>, certain prerequisites must be met on the target Windows servers. These steps ensure secure and reliable remote communication between the server and Viewtilog.</p><hr><h2><strong>1. Enable and Configure WinRM</strong></h2><ul><li><p>Open <strong>PowerShell as Administrator</strong>.</p></li><li><p>Run the quick configuration command:</p><pre><code class="language-powershell">winrm quickconfig
</code></pre></li></ul><p>Enable basic authentication:</p><pre><code class="language-powershell">winrm set winrm/config/service/Auth '@{Basic="true"}'</code></pre><p>Increase the maximum message size and concurrent operations:</p><pre><code class="language-powershell">winrm set winrm/config '@{MaxEnvelopeSizekb="1024"}'
winrm set winrm/config/service '@{MaxConcurrentOperationsPerUser="1500"}'</code></pre><p></p><h2><strong>2. Create a User for WinRM</strong></h2><ul><li><p>Create a dedicated user (if needed):</p><pre><code class="language-powershell">New-LocalUser "WinRMUser" -Password (ConvertTo-SecureString "Password123!" -AsPlainText -Force)
</code></pre></li><li><p>Add the user to the <strong>Remote Management Users</strong> group:</p><pre><code class="language-powershell">Add-LocalGroupMember -Group "Remote Management Users" -Member "WinRMUser"
</code></pre></li></ul><h2><strong>3. Configure Secure Authentication (HTTPS)</strong></h2><ol><li><p>Generate or install a <strong>Server Authentication Certificate</strong>.<br>Example of self-signed certificate:</p><pre><code class="language-powershell">$hostName = $env:COMPUTERNAME
$hostIP = (Get-NetAdapter | Get-NetIPAddress).IPv4Address | Out-String
$srvCert = New-SelfSignedCertificate -DnsName $hostName, $hostIP -CertStoreLocation Cert:\LocalMachine\My
</code></pre></li><li><p>Link the certificate to WinRM:</p><pre><code class="language-powershell">winrm create winrm/config/Listener?Address=*+Transport=HTTPS '@{Hostname="your-server-fqdn"; CertificateThumbprint="THUMBPRINT"}'
</code></pre></li><li><p>Configure the service to use encrypted communication:</p><pre><code class="language-powershell">winrm set winrm/config/service '@{AllowUnencrypted="false"; CertificateThumbprint="THUMBPRINT"}'
</code></pre></li></ol><h2><strong>4. Verify Available Groups for the WinRM User</strong></h2><ul><li><p>Ensure that the WinRM user has the necessary group memberships:</p><ul><li><p><strong>Remote Management Users</strong> (mandatory).</p></li><li><p><strong>Performance Log Users</strong> (to query performance counters).</p></li><li><p><strong>Event Log Readers</strong> (to read event logs).</p></li></ul></li><li><p>To check groups:</p><pre><code class="language-powershell">net user WinRMUser</code></pre></li></ul><h2><strong>5. Enable WMI Permissions</strong></h2><ul><li><p>Open <strong>wmimgmt.msc</strong> (WMI Management Console).</p></li><li><p>Right-click <strong>WMI Control (Local)</strong> → <em>Properties</em>.</p></li><li><p>Go to <strong>Security</strong> tab → expand <em>Root</em> → select <strong>CIMV2</strong>.</p></li><li><p>Click <strong>Security</strong> → Add the <strong>WinRM user</strong>.</p></li><li><p>Grant <strong>Remote Enable</strong> and <strong>Execute Methods</strong> permissions.</p></li></ul><p></p><h2><strong>6. Configure DCOM Access</strong></h2><ul><li><p>Open <strong>dcomcnfg</strong> (Component Services).</p></li><li><p>Navigate to: <em>Component Services → Computers → My Computer</em>.</p></li><li><p>Right-click → <strong>Properties</strong> → <em>COM Security</em>.</p></li><li><p>Under <strong>Launch and Activation Permissions</strong>, click <strong>Edit Limits</strong>.</p></li><li><p>Add the <strong>WinRM user</strong> and grant:</p><ul><li><p><strong>Remote Execution</strong></p></li><li><p><strong>Remote Activation</strong></p></li></ul></li></ul><p></p><h2><strong>7. Enable Event Logon Auditing</strong></h2><p>To capture user login events (e.g., Event IDs 4624, 4625), enable logon auditing:</p><ol><li><p>Open <strong>Local Security Policy</strong> (<code>secpol.msc</code>).</p></li><li><p>Navigate to: <em>Local Policies → Audit Policy</em>.</p></li><li><p>Enable:</p><ul><li><p><strong>Audit logon events (Success, Failure)</strong></p></li><li><p><strong>Audit account logon events (Success, Failure)</strong></p></li></ul></li></ol><p></p><h2><strong>8. Firewall Rules</strong></h2><p>Enable incoming traffic on the default WinRM HTTPS port (5986):</p><pre><code class="language-powershell">netsh advfirewall firewall add rule name="WinRM HTTPS" protocol=TCP dir=in localport=5986 action=allow</code></pre><hr><p></p><h2><strong>9. Certificate Export and Conversion</strong></h2><ul><li><p>Export the certificate to <strong>.cer</strong>:</p><pre><code class="language-powershell">Export-Certificate -Cert $srvCert -FilePath "C:\Temp\winrm_server.cer"</code></pre></li><li><p>Copy the <code>.cer</code> file to the server where <strong>Viewtilog</strong> runs. This ensures trust in the secure connection.</p></li><li><p>If Viewtilog requires a <strong>.pem</strong> format, convert the <code>.cer</code> file using OpenSSL:</p><pre><code class="language-powershell">openssl x509 -inform DER -in winrm_server.cer -out winrm_server.pem
</code></pre></li></ul><hr><p></p><h3>⚠️ Disclaimer</h3><ul><li><p>The <strong>language of the operating system</strong> must be considered. Group names (e.g., <em>Remote Management Users</em>, <em>Event Log Readers</em>) may differ depending on whether Windows is in English, Spanish, or another language. Adjust accordingly.</p></li><li><p>Deleting or replacing the certificate may interrupt the connection. Always keep a backup of the <code>.cer</code> and <code>.pem</code> files.</p></li></ul><p></p>
