<h1><strong><span align="center">Flow Emitter Connector</span></strong></h1><p>The <strong>Flow Emitter Connector</strong> is a special-purpose connector within Viewtinet, designed exclusively for integration with <strong>Viewtimon</strong>. Unlike other connectors (such as SNMP, ICMP, or CSV), which interact with <strong>external data sources</strong>, the Flow Emitter is <strong>not intended for external use</strong>. Instead, it operates internally within the Viewtinet platform to expose data that has already been <strong>classified and analyzed by the DPI engine</strong> (Deep Packet Inspection).</p><p>The connector extracts DPI-processed information and exports it as <strong>plain text records</strong>, making it available for further transformation or loading into different data stores.</p><p>This connector is fundamental when leveraging Viewtimon’s advanced traffic classification, as it transforms detailed per-flow data into structured fields for downstream processing.</p><p></p><h2><strong>Key Characteristics</strong></h2><ul><li><p><strong>Internal use only</strong> → tied to Viewtimon DPI engine, not for external devices.</p></li><li><p><strong>Exports DPI-enriched flow data</strong> into text format.</p></li><li><p>Provides <strong>fine-grained metrics</strong> on IP traffic, TCP/UDP sessions, DNS queries, jitter, retransmissions, application names, and more.</p></li><li><p>Fully integrated into the ETL process, ensuring Viewtinet’s DPI capabilities can be correlated with logs, SNMP counters, or other extracted sources.</p><p></p></li></ul><h2><strong>Field Examples</strong></h2><p>The Flow Emitter outputs a large set of <strong>predefined fields</strong>. Each field represents a specific KPI or metadata element detected by the DPI engine. Some examples include:</p><ul><li><p><strong>Basic Network Identifiers</strong></p><ul><li><p><code>net_src_ip</code>, <code>net_dst_ip</code>: Source and destination IP addresses.</p></li><li><p><code>net_src_port</code>, <code>net_dst_port</code>: Source and destination ports.</p></li><li><p><code>ip_protocol</code>: Protocol number (e.g., TCP, UDP, ICMP).</p></li></ul></li><li><p><strong>ICMP Metrics</strong></p><ul><li><p><code>icmp_rtt</code>: Round-trip time for ICMP probes.</p></li><li><p><code>icmp_packet_loss</code>: Percentage of ICMP packet loss.</p></li></ul></li><li><p><strong>TCP Metrics</strong></p><ul><li><p><code>tcp_rtt_client</code>, <code>tcp_rtt_server</code>: Round-trip times for client and server.</p></li><li><p><code>tcp_time_to_first_byte</code>: Time elapsed until the first byte is received.</p></li><li><p><code>tcp_retransmissions_client</code>, <code>tcp_retransmissions_server</code>: Retransmission counters.</p></li><li><p><code>tcp_window_size_client</code>, <code>tcp_window_size_server</code>: TCP window sizes.</p></li></ul></li><li><p><strong>Application-Level Metrics</strong></p><ul><li><p><code>app_name</code>: Application detected by DPI (e.g., HTTP, Skype, YouTube).</p></li><li><p><code>dpi_name</code>: DPI classifier name.</p></li><li><p><code>policy_id</code>, <code>policy_name</code>: Associated policy rules.</p></li></ul></li><li><p><strong>Performance Indicators</strong></p><ul><li><p><code>volume_uplink</code>, <code>volume_downlink</code>: Total traffic volume per flow.</p></li><li><p><code>app_jitter</code>, <code>app_packet_loss</code>: Application jitter and packet loss.</p></li><li><p><code>dns_query_count</code>, <code>dns_response_count</code>: DNS request/response counters.</p></li></ul></li><li><p><strong>Additional Context</strong></p><ul><li><p><code>host</code>, <code>url</code>: Application-level information (e.g., HTTP host header, URL).</p></li><li><p><code>vlan_id</code>: VLAN tag associated with the traffic.</p></li><li><p><code>session_duration</code>: Lifetime of the detected flow.</p></li></ul></li></ul><p></p><h2><strong>Usage Notes</strong></h2><ul><li><p>The Flow Emitter Connector is <strong>not configurable with external parameters</strong> like IPs, ports, or OIDs. Its field set is fixed and depends on the DPI engine’s capabilities.</p></li><li><p>Data extracted with this connector is generally passed through the <strong>Transform stage</strong> (Grid Handlers) for normalization, enrichment, or mapping before being stored by a Producer.</p></li><li><p>Because of its DPI origin, this connector is ideal for scenarios requiring <strong>deep traffic visibility</strong> such as application performance monitoring, QoE analysis, or advanced troubleshooting.</p></li></ul><h3></h3><p></p>
