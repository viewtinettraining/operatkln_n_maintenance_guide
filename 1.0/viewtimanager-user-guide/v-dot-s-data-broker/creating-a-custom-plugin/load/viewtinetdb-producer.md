# **<span align="center">ViewtinetDB Producer</span>**

<br />

The **ViewtinetDB Producer** is the primary handler used to load the final grid obtained during the Extract stage and processed through the Transform stage directly into the local Viewtinet database.

This is the most common destination when you want to ingest parsed data for long-term storage, allowing you to later query, visualize, and build dashboards in the Viewtinet Console.

---

## **Configuration Parameters**

Once you select `ViewtinetDB Producer` from the dropdown menu, the system automatically populates most of the necessary variables for you, connecting directly to the internal database engine.

<br />

<figure align="center"><img src="https://viewtinettraining.github.io/viewtinettraining635.github.io/images/viewtinetdb-producer-step1.png" align="center"></figure>

<br />

### **Connection Variables (Auto-configured)**

-   **Engine**: Set to `postgres` by default.
-   **Host**: Resolves automatically using the macro `${DEFAULT_CONNECTOR_HOST}`.
-   **Port**: Default database port (`5433`).
-   **Database**: The core database name (`viewtinet`).
-   **User / Password**: Pre-configured with the internal system credentials to establish a secure local connection.

### **Ingestion Variables**

-   **Table**: This is a crucial field. By default, the name of the destination table is automatically taken from the **Pipeline Name** configured in the Extract stage. However, if you desire, you can directly override this field to specify a different custom table name.
-   **Save Mode**: Determines the behavior when writing data to the destination table. The most common configuration is **Append If Exists**, which safely appends new rows if the table is already present, or creates a brand new table with the grid's columns if it does not yet exist.
-   **Insert Mode**: Defines how the data is injected into Postgres. Generally set to `copy` for high-performance bulk loading.
-   **Batch Size / Null Repr**: Used for advanced fine-tuning of the data ingestion chunks and null string representations.

<br />

### **Manual Columns Definition (Optional)**

At the bottom of the producer, you will find an **\+ ADD NEW COLUMN** button. Usually, the Producer automatically inherits and creates the database columns based on the grid generated by the Transform handlers. However, you can explicitly define columns and their SQL data types here if you need strict, manual control over the database schema creation.
